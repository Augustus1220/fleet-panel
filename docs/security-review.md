# 安全审查

本仓库由一套**正在生产运行**的系统泛化而来。发布前的审查目标是：任何
能定位、接管或画像真实部署的信息都不进入仓库——包括 git 历史。

## 泛化方法

- 不是给生产仓库改名，而是从生产代码**逐项改写**出模板版：真实域名
  → `*.example.com`，真实 IP → 文档保留段 203.0.113.0/24
  （TEST-NET-3，RFC 5737），真实账号 → `alice_*` / `bob`，服务名、路
  径、Cookie 名统一换成 `fleet-*` 命名空间；
- 配置模板从生产配置的**结构**重写：保留全部字段与拓扑，只把 UUID、
  密钥、密码、token、代理凭据换成占位符；
- 仓库以全新 git 历史初始化，生产仓库的历史不带入。

## 自动扫描（发布前执行，全部无命中）

1. 敏感词黑名单：生产域名、服务器 IP、住宅出口 IP、账号名、人名、邮
   箱、非标准 SSH 端口、代理账号；
2. UUID 正则；
3. 私钥材料（`BEGIN ... KEY`、Reality privateKey 形态）；
4. 全部 IPv4 字面量逐一核对：只允许 0.0.0.0、127.0.0.1、公共 DNS、
   fake-ip 段与 TEST-NET-3；
5. 长随机串（≥24 位）逐一人工核对，均为占位符或节点名。

代码侧另有保障：面板的泛化版在沙箱中用伪造数据完整渲染过全部片段，
确认改写没有破坏功能、也没有残留引用。

## 永远不要提交的东西

真实部署中以下文件只存在于服务器本地，已全部写进 `.gitignore`：

- `payload.json`（含订阅 token——链接即钥匙）；
- 任何真实的 `config.json`（Xray：含 Reality 私钥与全部 UUID）、
  HY2 配置（含账号密码与统计 secret）；
- `password.json`（面板密码的哈希也不行）、`webshare.key`（住宅代理
  API key）、住宅代理的连接凭据；
- `links.json`、`status.json`、`history.sqlite3` 等运行时数据（包含
  真实链接与用量）；
- SSH 私钥、acme 账户与证书私钥。

## 外部审查后已落实的修复（2026-11-22）

首个公开版本经外部安全审查后，以下两项已同步进模板与生产部署：

- **代理出站私网拦截**：此前持有节点凭证的人可经代理访问服务器本机
  （127.0.0.1 上的统计/面板/订阅服务）与私网地址。现 Xray 模板在路由
  首条拦截私网/回环/链路本地/CGNAT 段（含域名解析后的目标，
  `domainStrategy: IPIfNonMatch`）；Hysteria2 模板在 ACL 首部
  `reject` 同一组地址段。生产环境修复前实测可达、修复后实测拒绝。
- **HY2 统计 secret 解析**：采集器以正则从 YAML 提取 trafficStats
  secret，原文带引号时会把引号一并当作密钥导致认证失败。现解析后剥
  离成对引号，模板中的示例 secret 也改为不带引号写法。

## 残余风险（请知悉）

模板版公开后，任何人都能知道这套系统的**架构与端口布局**。如果你的
生产部署与模板高度一致，等于公开了自己的系统蓝图。可选的缓解：生
产环境改用不同的面板/订阅端口、不同的服务命名；或只把面板部分开源、
架构文档保留在私有仓库。本仓库的文档描述的是方法，不是某一台具体
机器的现状——请始终保持这个距离。
